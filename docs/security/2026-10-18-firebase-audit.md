추가 검사에서는 **취소 알림 누락 시 구매 권한 유지**, **조회 요청에 대한 사용량 제한 부재**, **운영 진단 화면의 내부 해석 자료 노출**을 확인했다. Firebase에는 자동 백업·시점 복구·DB 삭제 보호·TTL 정책이 설정되어 있지 않았다. 실결제는 현재 꺼져 있으며 취소 동기화 문제는 결제 개통 전 해결해야 한다.

### F1 취소 웹훅 누락 시 권한을 회수할 대조 경로가 없음

**우선도 P1 — 실결제 개통 전 해결. 현재 운영 결제 설정은 비어 있음.**

- 위치: `src/app/api/saju/payments/confirm/route.ts:21`, `src/lib/saju/account.ts:22`, `src/lib/firebase/store.ts:174`.
- 조건: PortOne에서는 취소됐지만 알림 지연·누락·처리 장애로 DB 주문이 `PAID`에 남아 있다.
- 재현: 실제 Route Handler에 합성 주문과 취소된 provider 응답을 연결했다. 결제 확인 HTTP 상태 200, 리포트 조회 200, 생성 함수 호출 1회였다. provider 조회는 **0회**였다. 모델 호출은 모의 함수로 대체했다.
- 원인: 결제 확인 API는 DB가 `PAID`이면 외부 상태 확인 전에 반환한다. 조회·생성도 같은 DB 상태를 신뢰하며, 주기적 대조 작업은 없다.
- 영향: 환불된 구매가 계속 활성화되고, 생성 전 취소된 주문도 LLM 비용을 발생시킬 수 있다. 웹훅이 정상 처리되면 기존 취소 보호는 동작한다.
- 수정: 주문별 최근 검증 시각과 대조 상태를 저장하고, 오래된 구매 권한과 생성 직전 상태를 서버에서 재검증한다. 웹훅 재시도·실패 알림과 정기 대조를 함께 둔다. 잠깐의 PG 장애가 이미 구매한 콘텐츠 전체를 막지 않도록 열람 유예와 생성 제한을 별도로 설계한다.
- 완료 조건: 취소 알림을 의도적으로 건너뛰어도 제한된 시간 안에 취소가 반영되고, 새 생성은 차단된다. 취소 후 지연된 Paid 이벤트가 권한을 복구하지 않아야 한다.

### F5 만료된 인증·요청 제한 자료의 정기 삭제가 없음

**우선도 P2 — 보존기간과 저장량 관리.**

- 운영 Firestore TTL 조회: `fields: []`.
- 위치: `src/lib/firebase/auth.ts:38`, `:105`, `src/lib/firebase/store.ts:210`.

- CSP는 `base-uri`, `object-src`, `frame-ancestors`만 설정되어 있다. `script-src`/`default-src`가 없어 스크립트 삽입이 다른 경로로 생겼을 때 추가 방어가 약하다. 현재 사용자 이름/리포트는 React 텍스트로 출력되고 HTML 실행 경로는 찾지 못했다. 이번 검사에서 XSS 실행이 재현된 것은 아니다. nonce 기반 CSP를 Report-Only로 검증한 뒤 카카오·PortOne 동작을 확인하고 적용하는 순서가 적절하다.
