# 다봄 심화 명리 해석 규칙 v1

현재 규칙: `myeongri-2026.1` / `synthesis-2026.1` · 생성 입력: `calculated-observations-v2` · 해석 계획: `connections-v1` · 기본 프롬프트: `essay-v42-genz-connections`.

**현재 생성 경로는 10~11절을 따른다.** 6~9절의 코퍼스 연결과 고정 해설 전달은 이전 버전의 변경 이력이며 현재 생성·재시도에서는 사용하지 않는다.

## 목적과 경계

계산된 개인 사주에 더 많은 해석 근거를 연결한다. `lunar-javascript`와 `KoreanPolicyAdapter`의 역법·절기·사주 계산은 그대로 두고, 저장된 v1 명식에서 추가 근거를 계산한다. 기존 리포트 본문을 자동 재작성하거나 데이터·결제를 지우지 않는다.

구분하는 세 단계:

1. **관찰된 구성**: 어느 위치의 간지들이 어떤 표에 해당하는지. 재현 가능한 사실이다.
2. **조건부 해석**: 월령·통근·투출 등을 읽는 다봄의 명시적인 정책이다. 학파 공통의 확정 답이나 통계적 예측으로 취급하지 않는다.
3. **생활 설명**: LLM이 계산된 관찰과 용어의 계산상 정의를 바탕으로 새롭게 작성한다. 고정 해설·예시·조언은 모델 입력에서 제외한다. 고전 번역이나 직접 인용으로 소개하지 않는다.

## 원전·출처·라이선스

기존 사용자 라이선스 제한을 유지한다. 고전 한문 원문은 public domain이며, 한국어 번역서·현대 해설·타 서비스의 코드/문장은 복제하지 않는다. 아래 규칙표·한국어 해설·구현은 자체 작성했다. 웹 페이지의 현대 편집물이나 번역에 public-domain 표기를 확대 적용하지 않는다.

- [萬民英, 三命通會 卷二](https://zh.wikisource.org/wiki/三命通會/卷二): 論地支, 論人元司事, 論五行旺相休囚死, 論支元六合, 論支元三合, 論將星華蓋, 論咸池, 論六害, 論三刑, 論沖擊. 관계표와 신살의 고전상 구분을 확인한다. 고전의 차별적 인물 평가·재난·질병 예언은 가져오지 않는다.
- [三命通會 卷三](https://zh.wikisource.org/wiki/三命通會/卷三): 論十干祿, 論驛馬, 論天乙貴人. 천을귀인은 갑·무·경=축미, 을·기=자신, 병·정=유해, 임·계=묘사, 신=인오의 통행표를 사용한다. 고전에는 다른 구분도 함께 실려 있어 이 표가 유일하다고 주장하지 않는다.
- [滴天髓 원문](https://zh.wikisource.org/wiki/滴天髓): 월령·쇠왕·종화·체용을 별도로 고려하는 원칙. 아래 숫자 조건이나 보류 정책이 고전에 그대로 적혀 있다고 주장하지 않는다.
- [子平真詮 원문 영인본](https://upload.wikimedia.org/wikipedia/commons/f/fe/NLC416-11jh010455-35296_%E5%AD%90%E5%B9%B3%E7%9C%9F%E8%A9%AE.pdf): 월령 중심의 취격과 투출, 변화·성패를 구별하는 근거. 월령 용신과 현대 억부 용신을 같은 뜻으로 섞지 않는다.
- **육파**: 자유·축진·인해·묘오·사신·미술의 통행 대응을 자체 구현한다. 위 《삼명통회》의 육해·삼형 장에 이 육파표가 실렸다고 출처를 꾸미지 않는다. 파의 길흉을 상위 판정으로 사용하지 않는다.

## 1. 합·충·형·해·파

`advanced-myeongri.ts`의 `findAdvancedRelations`는 관계를 하나만 반환하지 않는다. 인해는 합과 파, 사신은 합·파와 삼형의 두 글자 관계가 공존할 수 있다.

- 육합·육충: 기존 대응을 유지한다.
- 육해: 자미 / 축오 / 인사 / 묘진 / 신해 / 유술.
- 육파: 자유 / 축진 / 인해 / 묘오 / 사신 / 미술.
- 자묘형: 두 위치에 자와 묘가 있을 때.
- 인사신·축술미: 두 종류만 있으면 `partial-triple`의 형 관계, 세 종류가 모두 있어야 `complete-triple`의 삼형. 같은 지지 중복으로 빠진 세 번째 종류를 대신하지 않는다.
- 자형: 서로 다른 두 위치의 진진·오오·유유·해해. 자기 위치를 자기 자신과 비교하지 않으며, 모든 중복 지지를 자형이라고 부르지 않는다.
- 삼합·방합의 완성된 구성도 감지한다. 이 정보는 합화 여부가 필요한 강약·격국 판단을 보류하는 데 쓴다. 오행의 변환이 확정됐다고 쓰지 않는다.

범위는 원국, 원국+현재 대운, 원국+대운+올해, 그리고 그 구성+개별 월운이다. 대운/세운/월운 관계에는 해당 운의 글자가 실제 참여해야 한다. 서로 다른 두 달의 글자를 합쳐 관계를 만들지 않는다. 모든 근거에 참여 위치·관계 종류·규칙 ID가 남는다.

## 2. 신살

v1은 **천을귀인·역마·도화·화개 네 종류**를 제공한다. 모든 신살을 포괄하는 표가 아니다.

- 천을귀인: 일간을 기준으로 각 지지를 조회한다.
- 역마·도화·화개: 년지와 일지를 각각 기준으로 조회한다. 기준을 근거에 기록하고, 같은 대상이 두 기준에서 일치해도 별도 신살 두 개로 부풀리지 않는다.
- 역마: 신자진→인, 인오술→신, 사유축→해, 해묘미→사.
- 도화: 신자진→유, 인오술→묘, 사유축→오, 해묘미→자.
- 화개: 신자진→진, 인오술→술, 사유축→축, 해묘미→미.
- 기준 지지와 같은 원국 위치도 조회 대상에 포함한다. 다른 학파의 제외 규칙과 혼용하지 않는다.
- 원국·올해·대운·월운의 조회 결과는 별도 범위다. 원국 신살을 올해 새로 생긴 사건으로 바꾸지 않는다.

본문은 도움을 받는 방법, 활동 범위, 자신을 보여 주는 방법, 집중과 배움 등 현대적 보조 의미로 연결한다. 혼인·외모·부정행위·질병·사고·직업을 신살로 확정하지 않는다.

## 3. 신강약: 계절·통근·천간의 합치 여부

오행 개수를 단순 합산한 점수, 운세 확률, 과학적 성격 검사로 사용하지 않는다. 내부에서는 아래를 각각 보관한다.

- 월지 본기를 기준으로 한 계절의 오행과 왕·상·휴·수·사 위치.
- 지장간에서 일간과 같은 오행의 뿌리가 있는 위치. 본기/부기를 나누고 해당 뿌리 지지의 충도 표시한다.
- 일간 자신을 제외하고 천간에 드러난 비겁·인성의 지지와 나머지 십신.

**다봄 자체의 보수적인 경향 후보 규칙**:

- 계절이 일간을 돕고, 충으로 다투지 않는 본기 뿌리가 있으며, 드러난 도움도 있으면 신강 쪽 후보.
- 계절의 도움이 없고, 본기 뿌리가 없으며, 드러난 도움이 한 곳 이하이면 신약 쪽 후보. 뿌리·도움이 모두 없는 특수 구성은 별도 보류.
- 그 밖에는 `undetermined`. 중화라고 확정하지 않는다.
- 시각 미상, 토월의 사령 미분석, 천간합 검토 필요, 완성된 삼합/방합의 합화 검토 필요, 무근·무조의 종격 검토 필요 시 보류.

이 규칙은 전문 감정 결과와 동일하다고 검증된 모델이 아니다. 보류할 때도 확인된 통근·지원 위치는 설명할 수 있으나, 신강/신약 명칭과 용신은 출력하지 않는다. 강약은 성격·건강·능력의 강약이 아니다.

## 4. 격국: 월령 중심 후보

- 월지 지장간과 **일간을 제외한** 원국 천간의 투출을 비교한다.
- 투출이 하나로 좁혀지는 십신을 월령 후보로 삼는다. 여러 지장간이 투출하면 모두 근거로 남기고 단일 격국 명칭의 본문 출력은 보류한다.
- 건록·양인·월겁의 월령 규칙은 별도로 구분한다. 양인은 양간만 사용한다. 무토의 오월 양인은 본기 정화가 아니라 기토의 겁재 관계를 근거로 기록한다.
- 시각 미상, 월지 합·충, 관련 천간합, 완성된 지지 집합 등 검토가 필요한 경우 보류한다.
- 무투출은 월지 본기만으로 확정하지 않는다. 특수격, 종격, 합화격, 성격/파격, 사회적 귀천 판정은 제공하지 않는다.

## 5. 용신: 억부 관점의 조건부 보완 방향

- 신강 후보: 일간이 생하는 식상 방향으로 힘을 쓰는 후보.
- 신약 후보: 일간을 생하는 인성과 같은 오행 비겁의 지원 방향 후보.
- 신강약 보류 시 용신 후보 목록은 빈 배열로 둔다.
- 단일 용신 확정, 희신/기신 등급, 조후·통관·종격·격국용신의 종합 판정은 하지 않는다. 부족한 오행을 곧 용신으로 정하지 않는다.
- 결과는 `conditional`, 명칭은 **억부용신 후보**다. 행운 색·물건·지역·투자 추천으로 확대하지 않는다.

## 6. 리포트 연결과 검증

`extractReportFacts` → `advanced`에 전체 관찰 결과를 보관한다. `buildAdvancedReportEvidence`가 실제 본문에 쓸 근거만 `CorpusFragment`로 만들고 flat `facts`에 연결한다.

- 올해 메시지: 실제 올해 글자가 참여한 형·해·파 등 보충 근거 한 묶음.
- 월운을 배정받은 주제: 그 날짜에서 확인된 심화 관계 한 묶음. 관계 관련 신살 한 종류는 관계 메시지에서 설명한다.
- 일·돈 메시지: 역마 및 조건을 충족한 월령 격국 후보.
- 마음 메시지: 통근·지지 근거, 가능한 억부 방향, 해당할 때 화개.
- 근거가 없으면 해당 fragment를 만들지 않는다. 후보 모두를 본문에 나열하지 않고 주제에 맞는 이유 하나를 쉬운 말로 잇는다.

전체 원시 관계·신살 표를 LLM에 중복 전송하지 않는다. 선택된 사실, 규칙 버전, 허용 용어, 판단 상태만 보낸다. 완성 생활 예문을 주입하지 않는다. 쉬운 반말·뜻 우선 표기·회색 괄호 설명·7~9개 표정·6개 주제 메시지 형식을 유지한다.

`advanced-report-rules.ts`는 배정되지 않은 신살/격국/강약/용신 명칭과 명시적인 확정 문구를 검사한다. 이 검사는 blocking이므로 스타일 복구로 우회하지 않는다. 한 글자 관계명은 일상적인 ‘형’, ‘해’, ‘파악’과 구별한다. 의미상 모든 오류를 검출하는 전문가 심사로 표현하지 않는다.

저장 메타데이터에 `interpretationRuleVersion`, `interpretationEvidenceIds`를 추가한다. 기존 문서는 이 필드 없이도 읽을 수 있다.

## 7. 주제 분리와 생성 시점 (2026-10-29)

- 코퍼스 `2026.6-distinct-topics`, 기본 프롬프트 `essay-v38-genz-distinct-topics`.
- `report-topic-corpus.ts`는 대운 십신별 돈의 질문 10종과 올해 십신별 연결점 10종, 일지 본기 십신별 가까운 관계의 보조 해석 10종을 제공한다. 모두 자체 작성한 현대 해설이다. 일지 하나로 연애 상태·배우자·관계의 성패를 판정하지 않는다.
- 올해 본문은 일·역할의 선택, 일·돈 본문은 대가·비용·남는 몫, 관계 본문은 가까운 관계의 소통과 월별 차이, 마음 본문은 내 판단과 외부 요구를 맡는다. `content_contract`를 최초 생성과 부분 재작성에 함께 전달한다. 원국의 배움·솜씨 보조 근거가 돈의 주제를 대신하지 않는다.
- 같은 정관이 있다는 이유만으로 새 역할을 피하라고 하지 않는다. 맡는 책임과 결정할 권한이 함께 주어지는지 구별하는 해석으로 수정했다. 기회·소득의 결과를 보장하지 않는다.
- `extractReportFacts`의 선택적 `asOf`는 실제 생성 시점을 기준으로 현재와 남은 월운을 최대 3개 고른다. 달력상 해당 연도의 남은 기간을 우선한다. 남은 기간이 하나면 하나만 쓰고, 연도가 넘어가는 날짜에는 다음 연도를 명시한다. 한 해가 모두 지났으면 회고로 구분한다. 기준일을 주지 않은 순수 추출은 기존 연간 선택을 유지한다.
- 합·충이 없는 현재 월은 실제 월간 십신으로 설명한다. 없는 관계를 만들거나 부재 자체로 분량을 채우지 않는다. 재시도는 저장된 `readingAsOf`를 재사용하여 절입 경계를 넘겨도 기존 초안의 날짜가 바뀌지 않는다. 완료된 리포트를 자동 재작성하지 않는다.
- 돈 내용 누락, 긴 문장 유사도, 진행 중인 해의 과거형 마무리는 문체 수정 신호다. 의미 전체를 평가하는 전문가 검증은 아니다. 기존 제한된 재시도·스타일 복구를 유지하며 명리 근거·개인정보 오류의 차단 규칙은 그대로 적용한다.
- 관계와 돈 메시지의 목표 분량만 각각 50자·30자 늘렸다. 전체를 무조건 길게 쓰지 않고 중복 설명을 줄이는 데 우선순위를 둔다.

실측 확인: 같은 테스트 명식으로 Luna 샘플 한 건을 별도 메모리 저장소에서 생성·부분 수정했다. 기존 Firestore 리포트는 읽거나 덮어쓰지 않았다. 최종 샘플은 6개 메시지, 1,972자이며 최종 검증에서 이슈가 없었다. 10·11·12월의 서로 다른 선택, 추가 작업의 대가와 비용 설명, 현재형 마무리를 확인했다. 한 샘플의 통과가 모든 사용자 출력의 품질이나 구매 만족도를 보장하지는 않는다.

## 8. 조언보다 운세 설명 (2026-10-29)

- 사용자 피드백: 행동 조언이 많아 운세를 읽는 느낌이 약했다. `report-fortune-reading.ts`에 십신 10종의 주제·기회·부담·돈·관계 의미와 방향이 구분된 5×5 기능 연결 해설을 추가했다. 원국·올해·대운의 실제 fact ID와 시간 범위를 함께 전달한다. 원국과 올해의 같은 주제는 반복되는 주제로만 읽으며 강약 점수나 격국 성립으로 바꾸지 않는다.
- 코퍼스 `2026.7-fortune-first`, 기본 프롬프트 `essay-v39-genz-fortune-first`, warm `essay-v34-fortune-first`. 본문은 운세 설명 80% 이상을 목표로 하고 조언은 주제당 최대 한 문장으로 제한한다. 최초 생성과 부분 수정 모두 `fortune_reading`을 전달한다. 기존 `decision_rule`은 선택적인 한 문장 조언의 보조 자료로 둔다.
- 월운은 기존과 같은 계산 기간·근거를 쓰되 달마다 할 일을 배정하지 않고 해당 십신과 실제 합충에서 읽는 관계 분위기의 차이를 설명한다. 날짜·시기·사건 확정 금지·쉬운 반말·특수문자 표정 정책은 유지한다.
- 조언 문장 탐지는 명시적인 지시·권유 패턴에 대한 보수적인 문체 신호다. 전체 문장의 의미를 판별하거나 운세 비율 80%를 자동 보증하지 않는다. 기존 제한된 스타일 재시도와 정상 초안 복구를 유지한다.
- 실제 샘플에서 연도 이름 `병오`가 올해 십신을 대신하는 오류를 발견해 올해 필수 근거를 실제 십신으로 좁혔다. 또한 `이해·올해·합리적·충분` 안의 음절을 괄호 용어보다 먼저 잡던 풀이 검사를 수정했다.
- 검증: 근거/주제 13그룹(370개 기준일·100개 조합), 생성·복구 120건, 개인화 9그룹, 실제 명식 60개·월 경계 48개, 표시·표정 검사 및 TypeScript/ESLint 통과. 계산 비교는 기존 29/30 일치와 입춘 정책 차이 1건을 유지한다.
- 실측: 실제 DB를 차단한 메모리 저장소에서 Luna 샘플 한 건을 생성·부분 수정했다. 총 API 요청은 4회이며 최종 6개 메시지 1,915자로 검증을 통과했다. 명시적 조언 패턴은 탐지되지 않았지만 조건부 권유의 의미가 완전히 없다는 뜻은 아니다. 이전 샘플과 신규 샘플은 `.firebase/reviews/`에 분리 보관하고 기존 사용자 리포트는 변경하지 않았다. 모델/API 지역과 개인정보 전송 범위도 그대로다.

## 9. 원국·대운·세운 종합과 주제별 시기 (2026-10-29)

- 파생 규칙 `synthesis-2026.1`, 코퍼스 `2026.8-chart-synthesis`, 기본 프롬프트 `essay-v40-genz-chart-synthesis`, warm `essay-v35-chart-synthesis`.
- `myeongri-synthesis.ts`가 기존 v1 명식에서 계산한다. 달력 계산, 절입·한국시간 정책, 모델 Luna/Global은 변경하지 않는다. 새 결과는 원본 명식을 수정하지 않고 `ReportFacts.synthesis`에 보관한다.
- **원국 종합**: 계절의 도움, 본기/부기 뿌리와 충 여부, 월지 지장간이 실제 천간에 드러난 위치를 함께 읽는다. 투출은 정확히 같은 천간, 통근은 같은 오행이다. 일간 자신은 투출의 증거로 세지 않는다. 시각 미상은 모든 새 관찰에서 시주를 제외한다.
- **대운 × 올해 × 원국**: 대운 천간에서 올해 천간으로 향하는 생·극, 올해에서 일간·원국 천간으로 향하는 생·극과 천간합을 각각 기록한다. 생을 이익, 극을 손해로 치환하지 않는다. 올해와 정확히 같은 글자가 원국의 겉/안에 있는지도 구별한다. 합은 관찰일 뿐 합화·오행 변환을 판정하지 않는다.
- `report-synthesis-corpus.ts`의 한국어 해석은 다봄이 자체 작성했다. 원국 관찰과 실제 생극 관계를 `primary_interpretation`으로 전달하여 올해/일·돈 메시지에 그 사주에서 읽는 이유 하나를 풀도록 한다. 조언이나 용어 개수를 늘리는 방식이 아니다. 생성 및 부분 수정 모두 같은 근거를 받는다.
- **주제별 월운**: 현재/남은 기간을 우선 고르는 기존 선택은 유지한다. `assignTopicTiming`이 선정된 최대 세 기간을 일(yearly)·돈(career)·관계(relation)에 중복 없이 배정한다. 십신에 따른 적합도는 편집 선택이며 길흉 점수·성사 확률·어떤 분야만 좋은 달이라는 판정이 아니다. 기간이 두 개 또는 하나면 그 수만큼만 배정한다. 월운의 형·해·파 보충 근거도 같은 날짜의 주제로 이동한다. 실제 시작·끝 날짜와 다음 해 표기는 그대로 검증한다.

### 조후의 적용 범위

근거는 [滴天髓 寒暖·燥濕 원문](https://zh.wikisource.org/wiki/滴天髓/16) 및 [三命通會 卷二](https://zh.wikisource.org/wiki/三命通會/卷二)의 계절·오행 구분이다. 무료로 이용 가능한 한문 원문만 참고했으며 현대 번역은 가져오지 않았다.

- 사·오·미는 더운 계절, 해·자·축은 차가운 계절, 나머지는 전환 계절의 지표로 둔다. 미·술의 조토, 진·축의 습토는 별도 지표다. 이는 실제 출생일의 기상이나 명식 전체의 온도·습도 수치가 아니다.
- 원국의 불·물이 겉/안에 놓인 위치를 기록한다. 개수로 전체 과다·부족을 확정하지 않는다. 올해 천간의 불/물 방향이 계절의 온도 방향을 더하는지, 반대 방향인지, 직접 비교하지 않는지를 구분한다.
- `seasonal-indicators-only`: 조후의 보조 관찰까지만 제공한다. 특정 글자의 조후용신 확정, 일간별 궁통보감 전체 처방, 억부·격국용신을 통합한 최종 감정은 아니다. 더움→급한 성격, 차가움→차가운 마음 또는 질병으로 연결하지 않는다.

### 십이운성의 적용 범위

- 일간 기준으로 원국 네 지지(시각 미상은 세 지지), 현재 대운·세운·각 월운 지지를 조회한다. 양간 순행·음간 역행, 무토는 병화·기토는 정화와 같은 궁을 쓰는 관례를 고정한다. 다른 학파의 토 운성표를 혼용하지 않는다.
- 장생 기준: 갑=해, 을=오, 병·무=인, 정·기=유, 경=사, 신=자, 임=신, 계=묘. 순서는 장생·목욕·관대·임관·제왕·쇠·병·사·묘·절·태·양이다.
- 원문에서 제시하는 생장·쇠퇴의 순환을 준비·표현·활용·정리의 현대적 보조 뜻으로 자체 해설한다. 고전의 직접 인용이나 검증된 미래 사건이 아니다. 실제 본문은 올해 운성 한 개만 보충 자료로 제공하며 조후와 함께 용어 나열로 만들지 않는다.
- 병·사=질병·죽음, 묘=무덤, 절=이별, 태·양=임신·출산으로 풀이하지 않는다. 제왕 한 글자로 신강·성공을 판정하지 않는다. 단어의 첫 등장에는 쉬운 뜻을 앞에 놓고 괄호 용어만 작은 회색 글자로 표시한다.

`advanced-report-rules.ts`는 배정되지 않은 운성, 조후용신·합화 확정, 운성에서 만든 건강·생사·임신 등의 명시적인 오류를 차단한다. `병원·사람·양쪽·형태` 같은 일상어와 괄호 용어는 구별한다. 이 패턴 검사가 모든 의미 오류를 탐지하는 것은 아니다. 저장 메타데이터에 선택된 `synthesisRuleVersion`, `synthesisEvidenceIds`를 남기며 기존 리포트는 자동 변경하지 않는다.

검증 결과: 신규 10그룹(십이운성 120개 조합 포함), 주제 13그룹(370개 기준일), 실제 명식 60개·월운 경계 48개, 개인화 9그룹, 생성/복구 122건, 심화 18그룹, 팩트 13건, 코퍼스 113건, 표시 9건, 표정 16건, TypeScript/ESLint를 통과했다. 만세력 비교는 기존 29/30 일치 및 입춘 정책 차이 1건을 유지한다.

실측 샘플은 실제 DB를 모든 메서드에서 차단한 메모리 저장소로 생성했다. 이름과 생년월일·시각 원문은 모델 입력에서 검사해 제외했다. 같은 한 건의 생성·부분 수정에 Luna 요청 5회가 사용됐다. 최종 6개 메시지 2,075자에서 계산·필수 시기·문자 검증은 통과했고, 올해 메시지 446자(권장 상한 400자)라는 문체 이슈 한 건은 남아 기존 제한된 복구 경로로 완료됐다. 이는 전체 문체 검사 통과라는 뜻은 아니다. 샘플은 `.firebase/reviews/report-synthesis-sample.html`에 두고 기존 저장 리포트는 유지했다. 새로운 원국 근거를 일반론 뒤에 덧붙이지 않고 설명의 중심에 놓도록 입력의 `fortune_reading.interplay`도 종합 해석으로 연결했다.

## 10. 고정 해설 제거 (2026-10-29)

반복의 원인: 같은 해설이 `primary_interpretation`, `fortune_reading`, fragment의 번역·전개 단계 등에 중복 전달됐다. 여러 본문이 역할·기대·부담이라는 같은 결론을 따라가고, 재시도에서도 같은 해설이 다시 주입됐다.

현재 흐름은 **계산 → 관찰 추출 → 주제별 관찰 ID 배정 → LLM 해석 작성 → 검증과 제한된 수정**이다.

- `report-payload.ts`는 코퍼스 모듈을 가져오지 않는다. 기존 코퍼스 파일과 라이선스 고지는 보관하되 생성 입력으로 연결하지 않는다.
- `observations`는 실제 간지·십신·계절·통근·투출·생극 관계·신살·십이운성 및 계산된 조건부 후보를 담는다. 관찰마다 하나의 상세 풀이 주제를 배정하고, 다른 주제에는 필요한 공통 배경 ID만 제공한다. 배정은 편집 기준이며 길흉 판정이 아니다.
- 월운은 정확한 기간 표 한 곳에 두고 관찰에서 인덱스로 참조한다. 해당 월의 관계·신살·운성도 같은 주제에 배정한다. 미선택 달, 시각 미상인 시주의 관찰, 보류된 강약·격국·용신 해설은 보내지 않는다.
- `report-definitions.ts`는 용어의 계산상 정의만 담는다. 성격·기회·부담·조언 문장이 아니다. LLM이 전체 사주에 맞는 의미를 쉬운 말로 풀이하며 정의 자체를 본문에 복사하지 않는다.
- `fortune_reading`, `primary_interpretation`, `translation`, `mechanism_steps`, `decision_rule`, 고정 예시를 최초·재시도 입력에서 모두 제거했다. 서로 다른 주제의 결론을 먼저 구분해 작성하도록 지시한다. 일·돈 검증도 모든 사주에 대가·비용·정산 이야기를 강제하지 않는다.
- 계산과 해석을 분리한다. LLM은 해석을 작성하지만 원국·세운·대운·월운의 값을 다시 계산하거나 없는 신살·격국·합화를 만들 수 없다. 후보는 후보로 유지한다. 자동 검사는 제한된 근거·문자·시점·유사 문구 검사이며 해석의 모든 의미를 검증하는 전문가 심사가 아니다.
- 여섯 메시지, 쉬운 반말, 뜻 다음 괄호 용어, 7~9개 특수문자 표정을 유지한다. 계산 엔진, Luna/Global, 결제·저장·조회 권한과 제한된 초안 복구 정책은 변경하지 않는다. 기존 완료 리포트는 자동 재작성하지 않는다.
- 회귀 검사는 고정 해설 필드가 최초·재시도 요청 어디에도 없음을 확인한다. 60개 실제 명식·48개 절입 경계·370개 기준일·시각 미상 불변성, 계산 근거의 참조 무결성 및 기존 생성 복구 검사를 유지한다.

## 11. 사주별 핵심 근거와 본문 사용 기록 (2026-10-31)

v41 실측에서 계산 관찰이 충분해도 빈 반복·통근 항목을 고정 출발점으로 삼고, 십신 정의를 일반적인 가능성 문장으로 늘이는 문제가 확인됐다. v42는 **계산 → 관찰 → 실제 구성에 따른 핵심 근거 선택·연결 질문 → LLM 풀이와 본문 사용 기록 → 근거/문체 검증**으로 보완한다.

- `report-reading-plan.ts`의 우선순위는 편집 규칙이다. 관찰된 올해의 충·결합, 실제 천간 반복, 계절과 세운의 연결 등을 비교하고, 주제마다 종류가 다른 핵심 근거 두 개를 고른다. 빈 통근·투출·반복 항목과 비교 불가한 계절 지표는 핵심 자료로 삼지 않는다. 숫자는 길흉·성공 확률이 아니다.
- 원시 관찰값은 보존한다. 계획의 `basis_ids`는 실제 주제 소유 근거만 참조하고, 기간은 `supporting_ids`로 둔다. 날짜 하나만으로 해석을 대신하지 않는다. 도입은 하나, 마무리는 새 근거 없이 본문의 결론을 요약한다.
- `connections`는 실제 사실과 연결 질문이다. 생극 방향은 행위 쪽·받는 쪽을 분리해서 적으며 `produced-by`를 뒤집지 않는다. 후보 상태·신살의 보조 범위는 유지한다. 준비된 결론·생활 장면·조언 문장을 넣지 않는다.
- `report-definitions.ts`에 십신의 현대적 해석 범주를 짧은 명사로 덧붙였다. 자체 작성한 분류이며 고전 번역·인용문이 아니다. 모델은 이를 실제 조합의 뜻으로 풀어야 하며 키워드 나열로 분량을 채우지 않는다.
- 최초 생성과 부분 수정 모두 같은 계획을 받는다. 본문은 중심 결론, 두 근거를 함께 읽는 이유, 가정임을 밝힌 생활 상황을 연결한다. 쉬운 반말·뜻 우선 괄호·7~9개 표정을 유지한다. 사건을 보장하지 않으면서 반복적인 가능성 문장을 줄인다.
- 기존 한 번의 Responses 요청 안에서 `paragraph`와 `evidence_uses`를 함께 받는다. 별도 심사 모델을 호출하지 않는다. 본문 네 주제에는 서로 다른 실제 근거 2~3개와 본문 속 구절을 기록한다. 하나 이상은 선택된 핵심 근거여야 한다. 존재하지 않는 ID, 다른 주제의 근거, 비어 있는 관찰, 본문에 없는 구절, 해당 근거의 용어·뜻·시점을 전혀 확인할 수 없는 구절은 초안 복구로 우회하지 않는다. 도입·마무리의 기록은 빈 배열이다.
- 이 검증은 **ID·주제 소유권·인용 일치·제한된 표현 검사**다. 인용 구절이 존재한다는 이유로 해석의 논리 전체가 증명되지는 않는다. 의미의 타당성과 읽는 느낌은 실제 리포트에서 추가 평가해야 한다. 내부 필드는 본문 노출 금지이며 UI에는 문장만 표시한다.
- 반복되는 가능성 문장은 제한된 재작성 대상이다. 재작성 실패 시 기존의 근거 검증 통과 초안만 복구하며, 추상성·주제 이탈·중복·조언 과다에 형식 문제보다 큰 벌점을 주어 초안을 선택한다. `editorialReview`에 남은 문제 수와 구체성 문제 수를 기록한다. 복구를 전체 문체 검사 통과로 기록하지 않는다.
- `meta.evidenceUses`와 `beats`는 모델이 본문에서 사용했다고 기록하고 위 검증을 통과한 근거를 남긴다. 원래 배정한 모든 근거를 실제 사용한 것으로 기록하지 않는다. 재개·부분 수정 시에도 사용 기록을 보존한다. 과거 완료 리포트와 결제 상태는 바꾸지 않는다.

Structured Outputs 형식은 [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs)의 필수 필드·추가 속성 제한에 맞춘다. 스키마가 해석의 정확성까지 보증하는 것은 아니다. Luna/Global, 출력 토큰 상한과 최대 5회 시도는 유지한다. 이번 검증은 모의 API와 순수 계산으로 진행하며 추가 유료 샘플을 호출하지 않는다.

### 생성 시간 초과 복구 (2026-11-02)

- 생성·수정 예산은 100초, HTTP 경로는 120초, 브라우저 대기는 130초, 중복 생성 방지 잠금은 180초다. 적어도 5초가 남아야 다음 시도를 시작한다. 기존 45초 예산에서는 첫 초안 이후 수정 시간이 부족할 수 있었다.
- 스키마가 정상인 미완성 초안은 비공개 `renderCheckpointJson`에 저장한다. 같은 프롬프트·모델로 재시도할 때 기준 시점과 나머지 문단을 유지하고 실패 문단만 수정한다. 새 프롬프트·모델, 잘못된 체크포인트는 재사용하지 않는다.
- 체크포인트는 검증을 통과한 `content`와 별개다. 조회 API·화면·운세함에 노출하지 않고 완료 시 비운다. 리포트 문서 삭제 시 함께 삭제된다. 저장된 초안을 발행하기 전에도 모든 차단 검사를 다시 실행한다.
- 시간 초과가 직전 검증 오류를 덮어쓰지 않는다. 시도별 소요 시간, 오류 분류, 수정 대상, 토큰 수를 `generationDiagnostics`에 기록하며 본문·개인정보·제공자 오류 원문은 진단 로그에 쓰지 않는다.
- 제공자 오류·응답 거절·토큰 상한에 따른 미완료 응답은 동일 설정으로 즉시 연속 호출하지 않는다. 검증을 통과한 초안이 있으면 기존 복구 정책에 따라 발행하고, 없으면 사용자가 다시 시도할 수 있는 실패 상태로 둔다. 무한 생성이나 임의의 해설 대체는 하지 않는다.
