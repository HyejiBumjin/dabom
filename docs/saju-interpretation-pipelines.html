사주 서비스 · 해석 생성 파이프라인

해석 문장은 누가 만드는가 — 세 가지 흐름

계산(간지·십성·합충·용신)은 세 방식 모두 결정론적 코드가 담당합니다. 갈리는 지점은 딱 하나 — 계산 결과를 읽을 수 있는 문장으로 바꾸는 마지막 구간입니다.

결정론적 코드 우리가 보유한 콘텐츠 (자산) LLM 담당 실패 지점
공통 전제

계산은 무조건 코드가 한다

아래 세 방식 모두 이 단계까지는 동일합니다. LLM에게 간지 계산을 시키는 선택지는 없습니다 — 틀립니다.

방식 A

순수 템플릿 — 완성 문장을 전부 보유

품질 통제는 확실하지만, 조합마다 완성문이 필요해서 콘텐츠가 감당이 안 됩니다.

  • 같은 입력이면 항상 같은 출력 — QA와 검수는 제일 쉽습니다.
  • 일간 × 세운 십성 × 합충 × 용신 조합이 곱해지면 완성문 수만 개가 필요합니다.
  • 앞 문단 "재물운 좋음" + 뒤 문단 "지출 조심" 같은 충돌을 조정할 방법이 없습니다.
방식 B

LLM 단독 — 내용 판단까지 전부 위임

문장은 자연스럽지만, 내용의 근거가 없습니다. 명리 판단 자체를 LLM이 하게 됩니다.

  • 콘텐츠 제작 비용이 0 — 프로토타입·데모용으로는 제일 빠릅니다.
  • "화 과다"라고 JSON에 있는데 "화를 보충하세요"라고 쓰는 식의 모순이 나옵니다.
  • 단골이 재조회했을 때 다른 말이 나오면 서비스 신뢰가 깨집니다.
방식 C · 권장

하이브리드 — 내용은 코퍼스, 문장은 LLM

해석의 요지만 우리가 보유하고, LLM의 역할을 엮기 + 말투로 한정합니다.

  • 코퍼스는 완성문이 아니라 요지 단위 — "편관 세운 + 신약 → 압박 커짐, 이직 상반기 불리" 수준이면 충분합니다.
  • LLM 프롬프트: "이 재료만 사용해서, 이 톤으로 작성. 재료 밖 명리 판단 금지."
  • 입력이 결정론적이므로 말투 버전별로 캐시하면 LLM 비용은 사용자당 연 1회입니다.
방식 C 딥다이브

룰 엔진 6단계 — 2026년 병오(丙午)년 예시

예시 인물 고정: 일간 경금(庚) · 일지 자수(子) · 원국에 인(寅) 보유 · 신약 · 용신 토·금 (기신 화)

STEP 1세운 간지 확정

2026년 = 병오(丙午). 근거는 60갑자 순환 공식(또는 만세력 테이블)이고, 적용 기간은 입춘 기준으로 2026-02-04 ~ 2027-02-03입니다. 이 두 값이 이후 모든 계산의 입력이 됩니다.

STEP 2관계 피처 추출 — 근거는 전부 룩업 테이블

병오 두 글자를 원국·대운과 전부 대조해서 "사실 목록(facts)"을 만듭니다. 판단이 아니라 조회입니다.

계산결과근거 (룩업 테이블)
세운 천간 丙 vs 일간 庚편관 (화극금 + 양·양)십성 테이블 (10×10)
세운 지지 午 vs 일지 子자오충 — 일지가 충 당함지지 충 테이블 (6쌍)
세운 지지 午 vs 원국 寅인오 반합 (화국 방향)삼합 테이블 (4국)
오행 분포 재계산화 +2 → 화 편중 심화오행 카운트 (산술)
현재 대운 간지 vs 丙午합·충 여부같은 관계 테이블 재사용
화(火)의 길흉기신 → 부담스러운 해원국 용신 판정 결과
신살해·묘·미 띠면 삼재 해당띠 기준 단순 룩업

STEP 3룰 발동 — facts를 조건으로 필터링

룰 하나 = 조건 + 해석 조각 참조 + 영역 태그 + 우선순위. facts에 대해 조건이 참인 룰만 발동됩니다.

- id: R-081
  when: 세운.십성 == 편관 AND 원국.신강약 == 신약
  domain: [직장, 건강]
  tone: 주의
  priority: 80
  fragment: "책임·압박이 커지는 해. 승진 기회이지만 과로 주의.
             이직은 상반기 불리."

- id: R-134
  when: 세운.지지관계 CONTAINS 자오충 AND 충.궁위 == 일지
  domain: [애정, 변동]
  tone: 경고
  priority: 90
  fragment: "일지 충 — 배우자·거주지 등 일상 기반의 변동수.
             큰 계약·이사는 시기를 가릴 것."

STEP 4충돌 해소 · 선별

발동된 룰이 15~30개 나오면 그대로 다 넘기지 않습니다. 영역(domain)별로 priority 상위 2~3개만 남기고, 같은 영역에서 길·흉이 상반되면 삭제하는 대신 "상반된 신호 공존"이라는 메타 정보로 표시합니다 — "기회와 부담이 함께 오는 해"는 그 자체로 유효한 해석이니까요.

STEP 5월운 12회 반복

병오년의 월간지는 월두법으로 자동 결정(경인월부터 시작)되고, 각 월 간지에 STEP 2~4를 축소 적용해 월별 조각 1~2개씩 뽑습니다. 월 경계는 절입 시각 기준입니다.

STEP 6페이로드 조립 → LLM 전달

LLM에 넘어가는 최종본은 아래 하나의 구조화 객체입니다. LLM은 여기서 벗어난 판단을 할 수 없습니다.

{
  "profile":  { "일간": "경금", "신강약": "신약", "용신": ["토","금"] },
  "seun":     { "year": 2026, "ganji": "병오",
                "적용기간": "2026-02-04 ~ 2027-02-03" },
  "facts":    [ { "type": "십성", "value": "편관",
                  "basis": "丙(화) vs 일간 庚(금)" },
                { "type": "충", "value": "자오충", "궁위": "일지" }, … ],
  "fragments": [ { "id": "R-081", "domain": "직장", "tone": "주의",
                   "text": "책임·압박이 커지는 해 …" }, … ],
  "monthly":  [ { "month": "2026-02", "ganji": "경인",
                  "fragments": [ … ] }, … ],
  "outline":  [ "총운", "직장·명예", "재물", "애정·가정",
                "건강", "월별 흐름", "올해의 조언" ],
  "style":    { "톤": "친근한 존댓말", "분량": "영역별 2~3문장" },
  "constraints": [
    "fragments에 없는 명리 판단 금지",
    "facts와 모순되는 서술 금지",
    "outline 순서대로 작성, domain 태그로 영역 배치"
  ]
}

리포트의 목차(outline)도 우리가 정합니다. LLM이 하는 일은 fragments를 domain 태그에 따라 outline의 각 섹션에 배치하고, style대로 문장을 다시 쓰는 것 — 그게 전부입니다. 검증 단계는 출력에 fragments 밖 주장이 섞였는지만 대조하면 됩니다.

코퍼스 작성 팁: 조각은 완성 조합("경금 신약 병오년")이 아니라 규칙 단위("편관 세운 + 신약")로 씁니다. 조합은 룰 조건이 담당하므로, 세운 리포트 기준 수백 개 조각이면 시작할 수 있습니다.

코퍼스 · 조각 작성 가이드

조각은 "짧게"가 아니라 "밀도 있게"

조각에 담긴 정보가 많을수록 LLM의 재량이 줄고, 재량이 줄수록 환각과 QA 리스크가 줄어듭니다. 원칙: 담는 것은 내용, 빼는 것은 문체.

길이 다이얼 — 어느 쪽으로 틀어도 다른 방식의 실패로 회귀

수준예결과
너무 짧음 (키워드) "직장: 압박↑" LLM이 빈칸을 자기 지식으로 메꿈 → 방식 B의 환각으로 회귀
적정 (명제 2~4개, 정보 최대) 아래 예시 LLM은 문장 표면만 다듬음 — 뼈대는 전부 조각에서
너무 김 (문체 포함 완성문) 존댓말 완성 문단 조합·말투마다 재작성 필요 → 방식 A의 조합 폭발로 회귀

조각 하나에 담을 것 — 체크리스트

  • 방향 — 길인지 흉인지, 아니면 "기회와 부담 공존"인지
  • 영역 — 어디서 일어나는 일인지 (직장·재물·애정·건강…)
  • 조건·시기 — 언제, 어떤 경우에 (상반기 불리, 신약한 경우 심화 등)
  • 권고 — 그래서 어떻게 하라는 것인지
  • 강도 — 문장의 세기를 지시 (지나가는 언급 vs 올해의 핵심)
  • 근거 참조 — 어떤 fact에서 나온 판단인지

나쁜 조각 vs 좋은 조각

# 나쁨 — 키워드. LLM이 나머지를 지어내게 됨
text: "직장운 주의"

# 좋음 — 정보는 최대, 문체는 없음
id: F-081
text: >
  책임과 업무량이 뚜렷하게 커지는 해.
  승진·인정의 기회로 이어질 수 있으나, 신약한 명주에게는
  과로와 건강 소모로 나타나기 쉬움.
  이직·창업 등 큰 변동은 상반기 불리, 하반기부터 가능.
domain: [직장, 건강]
direction: 흉중길          # 방향
strength: 4                # 강도 1~5 — 서술 비중을 LLM에 지시
timing: { 불리: 상반기, 가능: 하반기 }
grounds: [세운.십성=편관, 원국.신강약=신약]

grounds를 명시해두면 LLM이 "왜냐하면 올해의 화 기운이…" 같은 근거 문장을 쓸 때 참조할 출처가 생기고, 검증도 필드 단위 대조로 내려가서 더 기계적으로 가능해집니다. strength는 리포트에서 이 조각이 한 문장짜리 언급인지 섹션의 중심인지를 결정합니다.

완성도 테스트

조각을 쓰고 나서 이 질문 하나로 검사합니다: "사람 작가가 이 조각만 받고, 추가 질문 없이, 새 주장을 보태지 않고 문단으로 늘릴 수 있는가?" — 아니오라면 정보가 부족한 것이고, 문단을 늘리는 데 조각의 문장을 그대로 베끼게 된다면 문체까지 박아버린 것입니다.

조각에 담는다 (내용)조각에서 뺀다 (문체 — style 가이드 담당)
명리적 판단 · 방향 · 강도 · 시기 · 조건 · 예외 · 권고 · 근거 존댓말/반말, 수사적 표현("찬란한"), 독자 호칭, 문단 연결어, 이모지

룰 + 조각 예시 5선 — 조건 축별로 하나씩

룰 조건이 참조하는 축은 십성 / 지지관계(+궁위) / 용신 / 대운 / 월운 다섯 가지이고, 대부분의 룰은 이 축 1~2개의 조합입니다. 그래서 수백 개 조각으로 커버가 됩니다.

# ① 세운 십성 기반 — 재물 (길한 케이스)
- id: R-042
  when: 세운.십성 == 정재 AND 원국.신강약 == 신강
  domain: [재물]
  direction: 길
  strength: 4
  grounds: [세운.십성=정재, 원국.신강약=신강]
  fragment: >
    노력의 결실이 돈으로 연결되는 해. 고정 수입 증가, 연봉 협상,
    성과 보상에 유리. 신강한 명주라 재물을 감당할 힘이 있어
    규모를 키워도 되지만, 투기성보다 실물·적립식이 맞는 구조.

# ② 지지 관계 기반 — 애정 (합)
- id: R-107
  when: 세운.지지 육합 원국.일지
  domain: [애정, 인연]
  direction: 길
  strength: 3
  grounds: [지지관계=육합, 궁위=일지]
  fragment: >
    일지가 합을 맺는 해 — 새로운 인연이 자연스럽게 다가옴.
    미혼자는 결혼 이야기가 구체화되기 좋은 시기,
    기혼자는 배우자와의 관계가 순탄해지는 흐름.

# ③ 삼합 + 용신 결합 — 건강 (복합 조건)
- id: R-155
  when: 세운.지지로 삼합 성립 AND 삼합.오행 == 원국.기신
  domain: [건강, 총운]
  direction: 흉
  strength: 5
  grounds: [삼합국=기신오행]
  fragment: >
    부담이 되는 오행이 국(局)을 이뤄 크게 강해지는 해.
    해당 오행이 상징하는 신체 부위(화라면 심혈관·눈·혈압) 관리 필요.
    무리한 확장과 감정적 결정이 문제를 키우는 구조라
    올해는 벌이는 해가 아니라 지키는 해.

# ④ 대운-세운 관계 — 변동
- id: R-201
  when: 대운.지지 충 세운.지지
  domain: [변동, 총운]
  direction: 주의
  strength: 4
  grounds: [대운지↔세운지=충]
  fragment: >
    10년 흐름(대운)과 올해 기운(세운)이 부딪히는 해 —
    환경 자체가 흔들리는 변동수. 이사·부서 이동·소속 변화가
    본인 의지보다 외부 요인으로 발생하기 쉬움.
    변동 자체는 막기 어려우니 선택지를 미리 준비해두는 것이 상책.

# ⑤ 월운 룰 — 조각이 짧아도 되는 케이스
- id: R-310

코퍼스 · 콘텐츠 소싱

조각의 글은 어디서 오는가

최종 소유는 우리가 하되, 전부 손으로 쓰지 않습니다. 고전에서 뼈대 → LLM으로 초안 → 전문가 감수로 확정. 감수를 통과한 조각만 런타임에 사용합니다.

소스 1명리 고전 — 판단의 뼈대 (저작권 프리)

자평진전(子平眞詮) · 적천수천미(滴天髓闡微) · 궁통보감(窮通寶鑑) · 연해자평(淵海子平) 등 고전 원문(한문)은 퍼블릭 도메인입니다. 반면 시중 한글 번역서·해설서·타 사주 사이트의 문장은 저작권이 있으므로 표현을 가져오면 안 됩니다. 요지(아이디어)는 저작권 대상이 아니라서, 조각을 "명제 단위 요지"로 쓰는 우리 구조가 이 경계를 지키기에 유리합니다.

고전을 쓰는 방법 세 가지:

  • 룰 조건으로 번역 — 고전 조문을 조건식으로 옮깁니다. 예: 「살중신경(殺重身輕)이면 제복이 필요하다」 → when: 세운.십성 == 편관 AND 원국.신강약 == 신약. 룰 목록 자체를 고전 목차에서 뽑을 수 있습니다.
  • LLM 초안 생성 시 참고자료로 주입 — 해당 조문 원문 발췌를 프롬프트에 첨부(RAG)해서, 초안이 LLM의 일반 지식이 아니라 고전 텍스트에 묶이게 합니다.
  • 출처 태깅 — 조각에 source: 자평진전 論偏官처럼 남겨두면, 리포트에서 "고전에서는 이 구조를 …라 봅니다" 같은 신뢰 요소로 쓸 수 있고 감수 때 원전 대조도 빨라집니다.
  • 주의: 고전끼리도 유파가 갈립니다. 기준 고전(유파)을 하나 정해 코퍼스 전체의 일관성을 유지하세요 — 감수자와 함께 결정할 사안.

소스 2LLM 초안 생성 — 구축 시점이므로 안전

"런타임에 LLM이 내용을 지어내면 안 된다"와 "구축 시점에 LLM으로 초안을 쓴다"는 다른 문제입니다. 후자는 사람이 검수한 뒤 박제되니까요. 파이프라인:

  • ① 룰 조건 목록 확정 — 십성 10 × 신강약 2~3 = 핵심 약 30개, 지지관계 × 궁위 ≈ 100여 개
  • ② 조건별로 아래 프롬프트에 고전 발췌를 첨부해 초안 생성 (배치)
  • ③ 감수 큐 — 전문가가 승인 / 수정 / 반려. status: approved만 런타임 사용
  • ④ 운영 로그 기반 보강 — 자주 발동되는데 조각이 없거나 빈약한 룰부터 채움. 발동됐는데 조각이 없으면 해당 영역은 짧게 처리하고 로그만 남김
# 초안 생성 프롬프트 (구축 시점 · 배치 실행)
역할: 명리 콘텐츠 초안 생성기. 창작하지 말고 참고자료 범위에서 작성.

입력 조건: 세운.십성 = 편관, 원국.신강약 = 신약
참고자료: [자평진전 論偏官 절 원문 발췌 — RAG로 주입]

작성 규칙:
- 명제 3~4개. 방향 / 영역 / 조건·시기 / 권고가 각각 드러날 것
- 문체 금지: 존댓말·수사·독자 호칭·이모지 없이 개조식 서술
- direction(길/흉/흉중길/길중흉), strength(1~5), grounds 제안 포함
- 참고자료에 근거가 없는 주장은 쓰지 말고 "감수 필요" 표시
- 참고자료의 문장을 번역·복사하지 말 것. 요지만 재구성

소스 3전문가 감수 — 생략 불가

감수 없이 LLM 초안만 쌓으면 "그럴듯한 코퍼스"가 됩니다. 이 아키텍처는 검증이 전부 코퍼스를 기준으로 돌기 때문에, 코퍼스가 틀리면 시스템 전체가 자신 있게 틀립니다. 상용 서비스들이 감수 역술인·명리 콘텐츠팀을 두는 이유이고, 감수를 통과한 코퍼스가 곧 서비스의 차별화 자산입니다. 조각에 status(draft/approved)와 version을 두고, 감수 이력을 남기세요.

리포트의 각 문단 끝 태그(R-xxx)는 그 문장이 어느 조각에서 왔는지의 추적 표시 — 실제 화면에는 노출하지 않지만 내부적으로 이 매핑이 있어야 8번 검증이 성립합니다.

문장의 근거는 우리 코퍼스, 문장 자체는 LLM. 계산 → 룰로 조각 선별 → LLM은 엮기·말투만 → 재료 대조 검증 → 캐시. LLM에게 명리 판단을 시키지 않는 것이 전체 구조의 핵심입니다.
