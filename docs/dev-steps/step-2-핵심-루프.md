# AI 사주 서비스 — STEP 2: 핵심 루프 구현

## 프로젝트 컨텍스트

AI 사주 MVP. Next.js 풀스택 + Prisma/PostgreSQL 세팅과 DB 스키마(User, SajuProfile, Product, Order, Report)는 완료된 상태다. 만세력 계산 모듈(내장 라이브러리 기반, 스파이크에서 검증 완료)이 `src/lib/saju`에 있다.

이번 단계 목표: 결제 없이 "입력 → 명식 계산 → GPT 리포트 생성 → 조회"가 끝까지 도는 핵심 루프를 완성한다. (결제 연동은 이후 단계에서 이 루프 앞에 붙임)

## 작업 요청

1. 사주 입력 페이지
   - 이름, 성별, 생년월일, 태어난 시간(**시:분 단위**, 모름 옵션 포함), 양력/음력(윤달 여부)
     - 시주 경계 판정에 분이 필요하므로 12지시 블록 선택이 아니라 시:분으로 받는다
   - 제출 → SajuProfile 생성 + 만세력 모듈로 명식 계산 후 myeongsik(Json)에 저장
   - 비로그인 상태에서도 입력 가능해야 함

2. 리포트 생성 파이프라인 (`src/lib/llm`)
   - Report 레코드 PENDING 생성 → 백그라운드에서 GENERATING → COMPLETED/FAILED
   - structured output으로 **에세이 본문** 생성:
     `{ paragraphs: string[], meta: { charCount, beats, termsUsed } }`
     - `paragraphs`: 소제목·번호 없이 순서대로 이어 읽는 단락 배열
     - `beats`: 글에 담긴 서사 비트 (`opening` / `past` / `career` / `money_love` / `mental` / `ending`)
     - `termsUsed`: 본문에 등장한 명리 용어와 그 풀이 `[{ term, gloss }]`
   - 저장 전 검증 (실패 시 저장하지 않고 재시도) — 톤 규칙은 STEP 3에서 확정하되 검증 훅은 여기서 만든다:
     - **분량**: 본문 합계 1,700~2,600자 (하한 미달 시 재시도)
     - **형식**: 인위적 소제목·번호 머리(`■`, `1.`, `##`, `[커리어]` 등) 미포함
     - **서사 비트**: 6개 비트 전부 커버
     - **용어 풀이**: `termsUsed`의 각 용어가 본문에 등장하며, 등장 직후 풀이가 함께 있는지
     - **금지어**: 비속어·금지 유행어 블랙리스트 미포함
   - 실패 시 자동 재시도 최대 3회(retryCount), 3회 실패 시 FAILED + lastError 기록
   - 프롬프트는 `src/lib/prompts/v1.ts` 형태로 버전 관리, Report에 promptVersion 기록
   - LLM에는 명식 JSON만 context로 제공하고, 명식 데이터를 벗어난 창작 금지 지시
     - 신살·대운·세운·월운이 명식 JSON에 값으로 들어 있어야 이 지시가 성립한다 (STEP 0 참고)

3. 리포트 조회 페이지
   - 생성 중: React Query 폴링으로 status 확인 + 로딩 콘텐츠("사주를 열어보는 중... 🔮")
   - 완료: **한 편의 긴 글로 렌더링** (모바일 우선)
     - `paragraphs`를 순서대로 단락으로 출력하고, LLM이 준 단락 구분을 그대로 보존한다
     - 문장을 임의 개수로 묶어 단락을 재구성하지 말 것 (리듬감이 깨진다)
     - 소제목·카드 그리드·섹션 구분선 없이, 편지/에세이를 읽는 흐름으로 배치
     - 스마트폰 가독성 기준으로 본문 폭·행간·단락 간격을 잡을 것
   - 동일 (sajuProfileId, productCode) 리포트가 이미 있으면 재생성하지 않고 기존 것 반환

4. 개발용 트리거: 입력 완료 화면에 "리포트 생성" 버튼(결제 대신 임시)

## 제약

- 명식 계산에 LLM 사용 금지 (결정론적 모듈만)
- LLM 호출 실패가 서버 전체를 죽이면 안 됨 (에러 격리)

## 검증

- 입력 → 생성 → 폴링 → 본문 렌더링 E2E 수동 확인
- 같은 프로필로 재요청 시 기존 리포트 반환(새 생성 없음) 확인
- OPENAI_API_KEY를 잘못 넣고 실행 → 3회 재시도 후 FAILED 기록되는지 확인
- 분량 하한 미달·소제목 포함 응답을 강제로 만들어 → 저장되지 않고 재시도되는지 확인
- 렌더링된 결과에 소제목·번호가 하나도 없고, 단락 구분이 LLM 출력과 일치하는지 확인
