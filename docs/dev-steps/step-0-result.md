# STEP 0 — 만세력 라이브러리 스파이크 결과

> 상태: 완료. `lunar-javascript`의 계산 범위와 외부 만세력 30건 대조를 끝내고, 서비스 시간 정책을 확정했다.

## 결론

`lunar-javascript`를 **기초 계산 라이브러리**로 채택할 수 있다. MIT 라이선스라 상용 서비스에 사용 가능하며, 런타임 외부 API 호출 없이 아래 데이터를 계산한다.

- 사주 원국 8글자(년·월·일·시주)
- 오행, 십신, 지장간
- 대운의 순행/역행·시작 시점·10년 주기
- 세운(유년)과 월운(유월)
- 절기 기준 연주·월주와 자시 계산 방식 선택(`sect-1` / `sect-2`)

제품은 라이브러리 결과를 직접 DB 계약으로 쓰지 않는다. 서비스가 소유하는 `Myeongsik` JSON으로 정규화해 저장하고, 그 JSON만 LLM에 제공한다.

## 외부 만세력 30건 대조

`sajuinfo.co.kr`을 기준 사이트로 삼아 30개 입력을 직접 대조했다. 비교 조건은 **서울 / UTC+9 / 태양시 보정 끔 / 조자시 방식 켬**이다. 29개 양력 입력과 1개 음력 윤달 입력을 포함했으며, 원국 8글자 기준으로 29건이 정확히 일치했다.

유일한 차이는 1995-02-04 입춘 당일 새벽 03:00이다.

| 정책 | 결과 |
| --- | --- |
| `sajuinfo.co.kr` | `乙亥 戊寅 丙寅 庚寅` — 입춘 **날짜**가 시작되면 연주·월주 전환 |
| `lunar-javascript` | `甲戌 丁丑 丙寅 庚寅` — 입춘 **절입 시각**(1995-02-04 15:12:51) 이후 전환 |

제품은 절입 시각을 정확히 반영하는 `lunar-javascript` 정책을 채택한다. 이 차이는 라이브러리 오류가 아니라 정책 차이이며, fixture에 `known-policy-difference`로 명시해 회귀 테스트에서 숨기지 않는다.

두 번째 기준인 Well Saju에서도 PRD 예시 입력의 원국 `乙亥 辛巳 辛亥 戊戌`, 대운, 2026 세운·월운을 교차 확인했다. 다만 2시간 시진 단위 입력만 제공하므로 분 단위 절입 시각의 기준 사이트로는 사용하지 않는다.

## 실행 방법

```bash
npm run saju:spike > /tmp/saju-spike.json
npm run saju:compare
```

`scripts/saju-spike.cjs`에는 PRD 예시 입력, 입춘 전후, 야자시·조자시, 1988년 서머타임 기간 케이스가 들어 있다. `scripts/saju-compare.cjs`는 `scripts/fixtures/sajuinfo-reference.json`의 30건과 라이브러리 결과를 비교한다.

## 확인된 API 결과

PRD 예시 입력(1995-05-20 20:20, 여성)을 `sect-2`로 계산하면 다음을 얻는다.

```json
{
  "pillars": ["乙亥", "辛巳", "辛亥", "戊戌"],
  "dayMaster": "辛",
  "fortuneCycle": {
    "direction": "forward",
    "startsAt": "2000-12-07 16:20:00"
  }
}
```

사용자가 제공한 예시 명식과 이 결과의 일주가 다르다. 어느 쪽을 제품 기준으로 삼을지는 라이브러리 결함으로 단정하지 않고, 국내 만세력 서비스와의 30건 대조 및 다음 정책 확정 후 결정한다.

## Step 1에서 구현할 항목

1. **일주 경계 정책** — `sect-1`(야자시를 다음 날)과 `sect-2`(당일)의 한국식 서비스 정책을 확정한다.
2. **신살 규칙** — 도화·역마·형살 등은 한국식 규칙 테이블을 별도 구현하고, 근거가 되는 원국·세운 값을 JSON에 남긴다.
3. 한국 출생지의 경도 보정 필요 여부와 적용 기준을 결정한다.

## 확정한 시간 정책

- **시간대**: 입력값은 출생지의 법정 현지 시각으로 받고, 한국 출생 기본값은 `Asia/Seoul`로 둔다.
- **절입**: 연주·월주는 절입 **날짜가 아닌 정확한 절입 시각**을 기준으로 계산한다.
- **자시**: MVP 기본값은 `sect-2`(조자시: 00:00~00:59를 해당 양력일)로 둔다. 야자시 정책은 입력 화면에서 나중에 선택 가능하게 확장할 수 있다.
- **서머타임**: IANA `Asia/Seoul` 기준 1987·1988년에만 적용한다. 이 기간 출생 기록은 KDT(UTC+10)에서 KST(UTC+9)로 1시간 환산한 뒤 계산한다.
  - 1987: 5월 10일 02:00 시작, 10월 11일 03:00 종료
  - 1988: 5월 8일 02:00 시작, 10월 9일 03:00 종료
  - DST 시작 시 사라진 02:00~02:59와 종료 시 중복되는 02:00~02:59는 자동 추정하지 않고, 나중에 입력 UI에서 사용자 확인을 받는다.

`lunar-javascript`는 만세력 계산 라이브러리이므로 이 역사 시간대 보정을 스스로 하지 않는다. 이후 `KoreanPolicyAdapter`가 이 정책을 적용한 시간을 라이브러리에 전달한다.

## 비교 기준과 근거

- 30건 fixture: `scripts/fixtures/sajuinfo-reference.json`
- 자동 비교: `npm run saju:compare`
- 1차 외부 기준: [무료만세력](https://sajuinfo.co.kr/) — 양/음력·윤달·태양시·조자시 옵션을 제공
- 2차 표본 교차 확인: [Well Saju](https://www.wellcoms.co.kr/saju/) — 기준 예시의 원국·대운·2026 세운/월운 일치 확인
- 역사 시간대 기준: [IANA Time Zone Database](https://www.iana.org/time-zones/tz-link), [서울 1988 DST 전환 기록](https://www.timeanddate.com/time/change/south-korea/seoul?year=1988)

## 채택 시 구조

```text
birth input
  → lunar-javascript (기초 만세력 계산)
  → KoreanPolicyAdapter (자시·서머타임·신살 보정)
  → Myeongsik JSON (versioned, DB 저장)
  → LLM essay prompt
```

이 구조에서 라이브러리는 교체 가능하고, LLM은 계산하거나 없는 사실을 창작하지 않는다.
