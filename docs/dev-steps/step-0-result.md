# STEP 0 — 만세력 라이브러리 스파이크 결과

> 상태: 진행 중. `lunar-javascript`를 1차 후보로 설치하고, API 지원 범위를 실행으로 확인했다.

## 1차 결론

`lunar-javascript`를 **기초 계산 라이브러리**로 채택할 수 있다. MIT 라이선스라 상용 서비스에 사용 가능하며, 런타임 외부 API 호출 없이 아래 데이터를 계산한다.

- 사주 원국 8글자(년·월·일·시주)
- 오행, 십신, 지장간
- 대운의 순행/역행·시작 시점·10년 주기
- 세운(유년)과 월운(유월)
- 절기 기준 연주·월주와 자시 계산 방식 선택(`sect-1` / `sect-2`)

제품은 라이브러리 결과를 직접 DB 계약으로 쓰지 않는다. 서비스가 소유하는 `Myeongsik` JSON으로 정규화해 저장하고, 그 JSON만 LLM에 제공한다.

## 실행 방법

```bash
npm run saju:spike > /tmp/saju-spike.json
```

`scripts/saju-spike.cjs`에는 PRD 예시 입력, 입춘 전후, 야자시·조자시, 1988년 서머타임 기간 케이스가 들어 있다.

## 확인된 API 결과

PRD 예시 입력(1995-05-20 20:20, 여성)을 `sect-2`로 계산하면 다음을 얻는다.

```json
{
  "pillars": ["乙亥", "辛巳", "辛亥", "戊戌"],
  "dayMaster": "辛",
  "fortuneCycle": {
    "direction": "forward",
    "startsAt": "2000-12-07 16:20:00"
  }
}
```

사용자가 제공한 예시 명식과 이 결과의 일주가 다르다. 어느 쪽을 제품 기준으로 삼을지는 라이브러리 결함으로 단정하지 않고, 국내 만세력 서비스와의 30건 대조 및 다음 정책 확정 후 결정한다.

## 아직 검증·구현할 항목

1. 국내 만세력과 30건 대조 — 입춘 직전/직후, 절기 당일, 야자시·조자시, 음력 윤달, 1987~88년 서머타임을 반드시 포함한다.
2. **일주 경계 정책** — `sect-1`(야자시를 다음 날)과 `sect-2`(당일)의 한국식 서비스 정책을 확정한다.
3. **시간 정책** — 한국 표준시와 1987~88년 서머타임을 서비스 코드에서 보정할지 결정한다.
4. **신살 규칙** — 도화·역마·형살 등은 한국식 규칙 테이블을 별도 구현하고, 근거가 되는 원국·세운 값을 JSON에 남긴다.
5. 한국 출생지의 경도 보정 필요 여부와 적용 기준을 결정한다.

## 채택 시 구조

```text
birth input
  → lunar-javascript (기초 만세력 계산)
  → KoreanPolicyAdapter (자시·서머타임·신살 보정)
  → Myeongsik JSON (versioned, DB 저장)
  → LLM essay prompt
```

이 구조에서 라이브러리는 교체 가능하고, LLM은 계산하거나 없는 사실을 창작하지 않는다.
